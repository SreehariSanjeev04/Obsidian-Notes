    MAC (Medium Access Control) Protocols

    • Single shared broadcast channel can lead to collision
    • MAC protocols are distributed algorithms that determines how node share channel.
    • Two broad classes: Channel partitioning and Random access

    Channel Partitioning MAC Protocols

    TDMA: Time division multiple access

    FDMA: Frequency division multiple access

    CDMA: Code division multiple access (same frequency and time but different code)

    Chanel Partition: Control

    • Assigned by a central coordinator (IEEE 802.11, Cellular networks)
    • Distributed consensus protocols
      • Nodes broadcast the time/frequency/code that they are going to use along with the duration. Done over a separate control channel.

    Collision Free Protocols

    Bit Map Protocol

    • Designed to guarantee that two nodes never transmit simultaneously

    • How it works: If there are $N$ nodes on the network, each frame cycle begins with $N$ mini-slots. If Node $k$ has a frame ready, it transmits a single 1 bit during mini-slot $k$.

    • Data Transmission: Once all $N$ mini-slots pass, every node knows exactly which stations want to send. Nodes then transmit their full data frames in numerical order without any risk of collision.

    Binary Counting Protocol

    • Equal length addresses assigned to nodes
    • Bit-by-Bit Broadcasting takes place, the one with higher order wins the lot
    • Can cause starvation

    Tree Walk Protocol

    • Slot 0 (Root Probe): In the first slot, permission to transmit is granted to the root node (which includes all nodes 0 to $N-1$).

    • Outcome Evaluation:

      • 0 Frames Sent (Idle): No node has data. Channel remains idle.

      • 1 Frame Sent (Success): Frame transmits successfully without collision.

      • $\ge 2$ Frames Sent (Collision): Two or more nodes transmit simultaneously. The protocol triggers a subtree split.

    • Subtree Division (On Collision):

      • The tree splits: Node access is restricted strictly to the Left Subtree (nodes $0$ to $\frac{N}{2}-1$) for the next slot.

      • The Right Subtree must remain silent until all collisions inside the left subtree are completely resolved.

      • If the left subtree suffers another collision, it splits recursively into its own left/right branches until single leaf nodes transmit individually without collision

      • Skipping higher levels during high load - adaptive

    Limited Contention Protocol

    Limited Contention Protocols are media access control (MAC) protocols that combine the advantages of collision-based protocols and collision-free protocols. They behave like slotted ALOHA under light loads and bitmap protocols under heavy loads, adapting dynamically to network conditions.

    Random Access Protocols

    Listen Before Transmit

    • When a node has packet to send, it senses the channel. If the channel is busy the it waits for random amount of time and then retry. All nodes use the same time frequency and code.
    • Collision - Exponential backoff
    • CSMA, CSMA/CA, CSMA/CD

    CSMA (Carrier Sense Multiple Access)

    • Even though a node listens to the channel before transmitting ("listen before talk"), signals travel through space at a finite speed (speed of light).

    • The Vulnerable Window ($\tau$): If Node A starts transmitting at time $t$, its radio signal takes a short amount of time ($\tau$, the propagation delay) to reach Node B.

    • If Node B senses the channel during this tiny time window before Node A's signal physically arrives, Node B will falsely detect an idle channel, begin transmitting its own frame, and cause a collision.

    Wasted Channel Capacity: Once a node begins sending a frame, it blindly finishes transmitting the entire frame. If a collision occurred at the very beginning of the frame, the entire transmission time for that packet is completely wasted.

    CSMA/CD (Collision Detection)

    • Core Philosophy: "Listen while talk."

    • Primary Environment: Wired networks (Ethernet / IEEE 802.3).

    • Mechanism:

      1. Sense: Node listens to the wire before sending.

      2. Transmit & Monitor: While sending data, the node continuously measures voltage levels on the wire to detect signal corruption (collisions).

      3. Abort & Jam: If a collision is detected mid-transmission, the node instantly stops sending data and broadcasts a short jam signal to alert all other nodes on the segment.

      4. Backoff: Sender nodes wait a random period computed via the Binary Exponential Backoff algorithm before re-attempting transmission.

    • Key Advantage: Minimizes channel time wasted on corrupted frames by cutting transmissions short immediately upon collision.

    CSMA/CA (Collision Avoidance)

    • Carrier Sense (Listen): The node checks the radio frequency.

      • If Busy: It waits until the channel becomes free.

      • If Idle: It moves to the next step.

    • Wait DIFS: The node waits for a fixed mini-pause called DIFS (Distributed Inter-Frame Space).

    • Random Backoff Countdown: The node picks a random timer (e.g., between 0 and 15 time slots). It counts down only while the channel remains quiet.

    • Transmit Data: When its countdown reaches zero, the node sends the data frame.

    • Wait for ACK: The receiver sends back an ACK (Acknowledgement) packet.

      • ACK Received: Transmission successful.

      • No ACK (Timeout): A collision occurred! The node doubles its random backoff window size (exponential backoff) and retries from Step 1.

    Channel partitioning MAC protocols:

    • share channel efficiently and fairly at high load

    • inefficient at low load: delay in channel access, 1/N bandwidth allocated even if only 1 active node 

    Random access MAC protocols

    • efficient at low load: single node can fully utilize channel

    • high load: collision overhead

    MAC Requirements in Sensor Networks

    • Primary Design Criteria: Energy efficiency, collision avoidance, scalability, and adaptivity to dynamic network sizes.

    • Secondary Design Criteria: Latency, fairness, throughput, and bandwidth utilization efficiency.

    Hidden and Exposed Terminal Problems

    • Hidden Terminal Problem:

      • Node $A$ transmits to Node $B$. Node $C$ is out of $A$'s range and cannot sense $A$'s signal.

      • $C$ senses the medium as idle, begins transmitting to $B$, and causes a collision at $B$.

      • $A$ is "hidden" from $C$, rendering Carrier Sensing (CS) and Collision Detection (CD) ineffective at $A$.

    • Exposed Terminal Problem:

      • Node $B$ is transmitting to Node $A$. Node $C$ wants to transmit to an unrelated node outside $B$'s range.

      • $C$ senses $B$'s carrier and defers transmission unnecessarily, even though its transmission to a distant node would not cause interference at $A$.

      • $C$ is "exposed" to $B$, leading to wasted spatial reuse

    IEEE 802.11 Distributed Coordination Function (DCF)

    • Handshake Mechanism: Resolves hidden/exposed terminal issues via Request-to-Send (RTS) and Clear-to-Send (CTS) control frames.

    • Deferral Protocol:

      • Nodes hearing the RTS defer transmission until the CTS exchange finishes.

      • Nodes hearing the CTS defer transmission for the duration of the upcoming DATA frame. The packet would have a timer specifying exactly how long the transmission will take

    • Failure Handling: If an expected CTS or ACK is not received, the sender initiates a backoff interval and retries.

    Energy Efficient Operation and Duty Cycling

    • Application Characteristic: Sense-response applications have extremely low event occurrence rates.

    • Energy Dynamics: Transceiver idle-listening energy consumption is comparable to active transmission ($T_X$) or reception ($R_X$) energy.

    • Solution: Radio Duty-Cycling. Radios remain powered off most of the time, powering on for brief, periodic listening slots to check for active traffic.

    The Time Uncertainty Problem

    • Core Problem: Senders and receivers operate on independent clocks. If sleep-listen schedules do not overlap, transmitted packets are lost.

    • Architectural Approaches:

      • Synchronous MACs: Nodes align sleep schedules (e.g., S-MAC, T-MAC).

      • Asynchronous MACs: Nodes operate on independent sleep cycles using preamble sampling or preamble frames (e.g., B-MAC, STEM).

      • Hybrid MACs: Combine clock offset prediction with variable preambles (e.g., UBMAC).

    Synchronous MAC Protocols

    Synchronous protocols require neighboring nodes to establish, maintain, and share a common sleep/wake schedule so their active windows overlap predictably.

    Limitation: Alignment overhead and low efficiency during low traffic S-MAC (Sensor-MAC):

    • Mechanics: Nodes form "virtual clusters" by exchanging periodic SYNC packets. All nodes within a cluster adopt identical sleep/wake schedules. Nodes at cluster boundaries (gateway nodes) follow multiple schedules, waking up during both to bridge communication.

    • Data Transfer: Uses an RTS (Request to Send) / CTS (Clear to Send) handshake during the active frame to prevent hidden terminal collisions before transmitting data.

    • Overhearing Avoidance - Non target nodes are put to sleep to prevent overhearing

    • Sleep Duration: Nodes read the Network Allocation Vector (NAV) field in detected RTS/CTS frames to set their sleep duration.

    • Drawback: Fixed active period lengths lead to energy waste when traffic is low (idle listening within the active slot).

    Node A: [ SYNC | DATA ]-------------------[ SYNC | DATA ]------------------- Node B: [ SYNC | DATA ]-------------------[ SYNC | DATA ]------------------- <--- Active ---><-- Sleep --> <--- Active ---><-- Sleep -->

    Asynchronous MAC Protocols

    Asynchronous protocols eliminate global clock synchronization overhead by shifting the burden of alignment entirely to either the sender or receiver using Low Power Listening (LPL) or Preamble Sampling.

    Sender: [ ======= Preamble Signal ======= ][ DATA ] Receiver: [Check]---------[Check]---------[Check/Receive DATA]

    Limitation: High energy consumption and channel occupation

    Hybrid MAC Protocols (Adaptive Preamble and Offset Tracking)

    Hybrid MAC protocols maintain asynchronous operational flexibility while minimizing the long preamble penalty by dynamically learning receiver schedule offsets.

    Sender:    [Delay / Sleep] -> [Short Target Preamble][ DATA ]
Receiver:                     [Check/Receive DATA]

    Message Parsing in S-MAC

    S-MAC amortizes a single RTS/CTS exchange across a whole sequence (burst) of data fragments. (Once the handshake is done, fragments are sent and ACK is received for each).

    Advantage: Better energy efficiency than sending long frames that may collide or short frames with RTS/CTS for each.

    S-MAC Evolution

    • Advantages (Wins): Idle listening energy is reduced via periodic sleeping, overhearing is minimized, and message passing cuts control overhead.

    • Drawbacks (Losses): Periodic clock synchronization imposes high signaling overhead (e.g., 1 SYNC packet per 15 seconds). Sleep intervals cannot be too long, or clock drift desynchronizes nodes.

    Timeout-MAC (T-MAC)

    • Enhancement over S-MAC: Introduces adaptive active duty cycle lengths instead of fixed active windows.

    • Operation: An active window ends dynamically if no activation events (e.g., timer timeouts, frame receptions, frame transmissions) occur within a fixed threshold timeout period ($TA$).

    • Performance: Achieves lower energy consumption than S-MAC under variable low-rate traffic, though latency increases.

    • Limitation: At very low data rates, periodic sync overhead makes asynchronous protocols more efficient.

    B-MAC

    • Objective: Provides a modular, low-footprint MAC protocol configurable by applications at runtime.

    • Three Core Components:

      • Clear Channel Assessment (CCA) combined with random backoffs.

      • Low Power Listening (LPL) using extended preambles.

      • In-band link-layer acknowledgments.

    Clear Channel Assessment in B-MAC

    • Problem: Overly pessimistic CCA wastes channel bandwidth; overly optimistic CCA increases collisions.

    • Key Insight: Environmental background noise varies across time and space, but active packet transmissions exhibit stable channel energy levels.

    • Software Noise Floor Estimation: Estimates the background noise floor using an exponential moving average of median RSSI measurements: $A_t = \alpha \cdot S_t + (1 - \alpha) \cdot S_{t-1}$, filtering out transient energy spikes.

    Low Power Listening

    • Mechanism: Receiver radios wake up periodically to sample the medium. Senders attach a long preamble ahead of the payload to ensure the receiver detects energy during its check.

    • Sizing Formula: $\text{Preamble Length} > 2 \times \text{Wakeup Time} + \text{Sleep Time}$.

    Longer check intervals generally extend node lifetime up to an optimal point

    B-MAC Evaluation

    • Advantages (Wins): Eliminates control packet overhead (no RTS/CTS or SYNC frames required) and supports arbitrarily long sleep durations.

    • Drawbacks (Losses): Transmitters must send worst-case preamble lengths for every frame, forcing unintended neighboring receivers to stay awake through long preambles.

    • Neutral Factors: Reduces channel fairness during long preamble transmissions and introduces latency.

    STEM (Sparse Topology and Energy Management)

    • Concept: Replaces continuous long preambles with repeated short wakeup frames containing target node destination addresses.

    • Mechanism: The target node parses the frame, recognizes its address, and replies with an ACK to stop further wakeup attempts.

    • Optimizations:

      • Can operate on a separate control channel using dual-radio systems.

      • Transmitters pause between frames to wait for an ACK before resending.

    Predictive Duty-Cycle Framework (Hybrid MAC)

    • Concept: Sender tracks and predicts the exact clock offset of target receiver nodes at runtime.

    • Optimization: Instead of transmitting maximum worst-case preambles or frame bursts, senders use shorter preambles tailored to the predicted clock drift.

    • Outcome: Reduces overall control overhead from preambles, wakeup frames, and SYNC transmissions

    UBMAC (Uncertainty-Driven Duty Cycling MAC)

    • Concept: Integrates Rate Adaptive Time Synchronization (RATS) with B-MAC.

    • Fixed Mode:

      • Uses a fixed preamble length of $x$ bytes, establishing a maximum allowable time uncertainty bound of $(x - 4) \times \text{byte time}$.

      • Employs RATS to maintain node clock drift within this bound.

    • Variable Mode:

      • RATS dynamically predicts current clock uncertainty.

      • Transmitters dynamically adjust preamble length to match $\frac{\text{Time Uncertainty}}{\text{Byte Time}}$.

      IEEE 802.15.4 (IEEE 802.15.4)

    • Scope: Defines PHY and MAC layer specifications for Low-Rate Wireless Personal Area Networks (LR-WPANs).

    • Target Applications: Industrial/commercial monitoring, personal healthcare, home automation (HVAC, lighting, security), consumer electronics, and PC peripherals.

    • Design Principles: Low power consumption, simplified implementation, and reliable data transmission.

    • Traffic Patterns Supported: Periodic sampling (e.g., sensor telemetry) and intermittent event-driven traffic (e.g., security alarms).

    • Medium Access Control:

      • Communication between PAN Coordinator and Slaves uses slotted or unslotted CSMA/CA.

      • Peer-to-peer traffic is unstandardized, leaving MAC implementation open to developers.

      • Star Topology: All peripheral devices communicate directly with a central PAN coordinator node.

      • Peer-to-Peer Topology: Devices communicate directly with adjacent nodes within range, forming mesh networks under overall PAN coordinator management.

      • Beacon Frame: Transmitted by the PAN coordinator to synchronize devices and bound the superframe.

    • Active Period (Superframe Duration, SD): Divided into 16 equal time slots (0–15):

      • Contention Access Period (CAP): Nodes compete for channel access using slotted CSMA/CA.

      • Contention Free Period (CFP): Dedicated Guaranteed Time Slots (GTS) assigned to low-latency applications.

      • Inactive Period: Radios enter deep sleep to conserve energy.

    Superframe Duration (SD) is the exact length of time (in symbols or milliseconds) that the active portion of the superframe lasts.
